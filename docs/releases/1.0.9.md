# OpenCanvas 1.0.9 交付记录

日期：2026-09-06<br>
交付定位：私有预览版

## 本版完成

- 新增一次性三步首次启动引导，说明数据归属、内容与空间分离、核心手势和备份边界；设置中可随时重新打开，自动化环境不会被引导阻塞。
- 新增“关于与诊断”，统一显示应用版本、运行模式、Electron、系统架构、知识库位置、保存状态和对象数量。
- 新增可复制的脱敏诊断摘要，不读取笔记正文、附件内容或文件清单；应用内可直接打开私有 GitHub 问题入口。
- 新增中文问题报告与功能建议模板，主动提醒反馈者遮盖私人内容。
- 新增本地优先隐私说明，明确当前版本没有后台同步、遥测、广告或自动更新请求。
- 新增 GitHub Actions 质量门禁，在主分支推送和合并请求中运行锁定依赖安装、全量构建与隔离 Electron 回归。
- CI 固定使用已验证的 Node 24.13.0 / npm 11.6.2，避免托管 runner 自动升级包管理器后改变可选 WASM 依赖的锁文件判定。
- 按 Electron 43 的新安装模型显式准备桌面运行时；已有且版本匹配时立即复用，全新克隆时调用官方安装脚本，使开发、Electron 回归和打包不再依赖旧版 `postinstall` 行为。
- 加固 Windows 外部文件监听：对子目录建立可恢复的非递归监听树，目录变化后自动刷新，并纠正 Node 在托管 Windows 环境中偶发返回的畸形相对路径；外部修改重载与冲突处理已经纳入完整 Electron 回归。
- 修正 Electron 回归对混合块格式的错误假设：混合选择显示“多种格式”时允许没有伪造的单一选中项，单一格式仍必须恰好选中一项。
- 项目正式采用 `GPL-3.0-only`，并在源码与安装包中同时提供项目许可证、第三方运行时依赖清单及完整许可证正文。
- 升级 Tiptap 到 3.31.3，修复旧版依赖公告；生产依赖和完整依赖的 `npm audit` 均为 0 漏洞，并加入 CI 安全门禁。
- CI 使用当前 Node 24 运行时的 `actions/checkout@v7` 与 `actions/setup-node@v7`，避免旧 Action 运行时弃用警告。
- 加固嵌套白板右键重命名的焦点交接：慢速 Windows 渲染器上，退出动画完成后输入框仍会稳定保有焦点。

## 已知边界

- Authenticode 实测状态仍为 `NotSigned`；没有受信任 Windows 代码签名证书，SmartScreen 可能显示未知发布者。
- 项目现采用 `GPL-3.0-only`；安装包同时携带 OpenCanvas 许可证及由锁定运行时依赖生成的第三方许可证清单。
- 现有 CI 是提交/合并请求质量门禁，不会自动签名或发布；稳定/测试通道和用户同意后联网的更新检查仍未实现。
- 升级前自动备份和正式降级政策尚未完成；当前应等待“已保存”并手动导出 OpenCanvas ZIP 与知识库目录副本。
