# OpenCanvas v2 程序内核

## 实体与视图分离

- `Card`：独立知识实体，正文以 Markdown 文件保存。
- `Board`：白板实体，只拥有视口、放置实例和连接。
- `BoardPlacement`：卡片、嵌套白板或自由文字在某张白板上的一次出现。
- `BoardConnector`：连接两个放置实例，而不是直接连接卡片实体。

因此同一张卡片可以在多张白板或同一张白板出现多次。正文修改会同步，坐标、尺寸、颜色保持独立。

## 版本与迁移

- v1：`notes + boards[].nodes + boards[].edges`
- v2：`cards + boards[].placements + boards[].connectors`
- v3：加入桌面空间布局和项目目录。
- v4：加入放置实例状态、附件关系、恢复元数据与完整性问题。

`normalizeWorkspaceSnapshot` 在内存中迁移旧结构。Markdown 文件不改变；旧白板只有在用户实际修改后才按 v4 保存。重复实体 ID 保留第一次出现的实体，危险相对路径会被收束在知识库内；缺失实体和断裂连线不会在载入时擅自删除，而是进入恢复中心等待用户处理。

无法解析的白板或笔记会以 `invalid-file` 报告，原文件留在原处。载入结果通过 `loadIssues` 把问题交给界面，因此“载入失败”和“知识库是空的”不会再混为一谈。

## 命令事务

画布操作通过命令历史记录 `before/after` 快照。拖动和缩放在 pointer down 时开始事务，在 pointer up 时提交，因此一次手势只产生一条撤销记录。新增、删除、连接、粘贴也进入同一历史系统。

画布同一时间只有一个交互状态：平移、框选、移动、缩放、连线或编辑。指针结束事件必须匹配启动手势的 pointer ID；系统取消、窗口外释放和工具切换会明确结束状态，连线来源不再由第二份布尔状态重复保存。

## 状态与写盘

工作区状态按数据、导航、文件、历史、编辑与界面通知等职责组合；组件使用只读选择器订阅所需片段，避免无关实体变化引发整页重算。

卡片、白板和桌面布局由统一调度器按实体去抖。同一实体的新写入替代尚未开始的旧写入，但已进入主进程的写入必须真正完成。关闭时先封住渲染层的新任务并排空队列，再由主进程停止接受新写入并等待所有原子替换结束，随后才关闭窗口。

原子写盘使用同目录临时文件。活跃临时文件会登记在当前进程的事务集合中，启动恢复、完整性检查和外部重载均不得回收这些文件；只有不属于活跃事务的残留才按崩溃恢复规则处理。

## 编辑器

卡片正文由 ProseMirror/Tiptap 编辑，支持标题、列表、引用、代码块、粗体和斜体。`@` 引用保存为普通 Markdown 链接：

```markdown
[卡片标题](opencanvas://card/<card-id>)
```

这样引用具有稳定 ID，同时仍是可读、可导出的文本。

编辑器只解析 Markdown 正文。文件开头的 YAML frontmatter 在进入编辑器前被分离，保存时按原字节重新拼接，因此未知字段和原有换行风格不会因正文编辑而丢失。编辑器扩展清单与 Markdown 往返测试共用同一配置，避免测试和实际编辑器能力偏离。

## 索引

工作区索引从本地文件派生，维护标签、反向链接和卡片放置位置。索引可重建，不锁定用户数据。
