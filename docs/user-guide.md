# OpenCanvas 完整用户手册

适用版本：1.0.10<br>
平台：Windows 桌面版；浏览器地址仅用于开发测试<br>
产品定位：单机、个人、本地优先的视觉知识工作区

> 最重要的一句话：**卡片 Markdown 保存内容，白板 JSON 保存引用和空间关系。** 同一张卡片可以出现在多个白板；移动白板上的实例不会移动 Markdown 文件，移除实例也不会自动删除原始卡片。

## 1. 安装与第一次启动

### 安装版与便携版

- 安装版会把 OpenCanvas 安装到你选择的位置，并创建系统入口。
- 便携版不需要安装，适合试用或临时运行。
- 当前私有预览安装包没有 Windows 代码签名。若 SmartScreen 显示“未知发布者”，请先确认文件来自项目的私有 Release，并核对发布页校验和；不要运行来源不明的同名文件。

### 默认知识库

第一次启动时，桌面版默认使用：

```text
文档/OpenCanvas Vault
```

该目录独立于程序安装目录。卸载 OpenCanvas 不应删除知识库，但重要资料仍应单独备份。

首次启动会显示三步引导，依次说明数据归属、卡片与白板的关系，以及最常用操作。引导只自动出现一次；以后可从“设置 → 帮助与首次使用 → 首次引导”重新打开。自动化测试环境会跳过引导，不影响回归脚本。

### 切换知识库

1. 点击左侧栏底部的知识库/保存状态。
2. 选择“切换知识库…”，或打开“设置”并选择“更改位置…”。
3. 选择另一个文件夹。

切换只会改变当前打开的位置，**不会**替你复制、合并、移动或删除原知识库。需要迁移时，先关闭写入并用文件管理器复制整个知识库，打开新位置检查无误后再决定是否处理旧目录。

## 2. 界面和核心概念

### 左侧栏

左侧栏提供四种主要入口：

- **桌面**：放置所有根级白板的无限画布。
- **白板**：查看和搜索白板，包括嵌套白板。
- **卡片**：查看和搜索所有卡片实体。
- **文件**：按真实 Markdown 目录浏览卡片和项目文件夹。

左侧栏底部显示知识库与保存状态，并提供设置、帮助和明暗主题。侧栏边缘可以拖动调整宽度，拖动时会显示高亮提示。

### 白板区域

- 左上角显示当前白板路径。父级名称和当前名称保持同一排版基线；当前名称可重命名。
- 画布工具包括选择、平移、连线、卡片、文字、Section 和嵌套白板。
- 缩放控件和小地图帮助定位大白板。
- 选中卡片后可在右侧栏持续查看；点击空白处取消选择不会自动折叠已经打开的侧栏。

### 实体和空间实例

理解以下区别可以避免误删：

- **卡片实体**：一份真实 Markdown 内容。
- **卡片实例（placement）**：卡片在某块白板上的一次出现，拥有自己的位置、尺寸和颜色。
- **独立副本**：复制出新的 Markdown 卡片，之后两份内容互不影响。
- **分身/引用副本**：新增同一卡片的空间实例；任意实例编辑正文，其他实例同步显示。
- **白板实体**：一份 `.board.json` 空间文档。
- **嵌套白板实例**：某块白板在桌面或另一块白板中的预览和入口。

## 3. 桌面与白板导航

### 桌面

桌面不是列表，而是一张可缩放、可平移的画布。每个根级白板以统一的白板预览卡显示，预览会概括其中的卡片和子白板。

- 拖动白板预览改变它在桌面的位置。
- 调整预览尺寸改变桌面排版，不会改变白板内部内容。
- 双击预览进入白板。
- 新建根级白板后，它会出现在桌面。

### 路径与返回

进入嵌套白板后，左上角会显示来源路径。点击上级白板名称可返回指定层级；返回箭头回到刚才的来源。由于同一白板可能从多个父级被引用，路径代表本次进入路线，而不是唯一文件目录。

### 重命名和删除

- 在标题位置启动重命名后，输入框会沿用标题的字号、行高和宽度，按 `Enter` 确认，按 `Esc` 或点击空白处取消。
- 从白板右键菜单删除时，先阅读影响提示。移除某个嵌套实例与删除白板实体不是同一件事。
- 删除有其他引用的白板前，应检查引用影响；不要把“在当前画布不再显示”误认为“文件已经删除”。

## 4. 卡片：创建、选择、编辑和复制

### 创建

按 `N` 或选择卡片工具：

- 在画布单击，使用默认尺寸创建卡片。
- 在画布拖动，按拖出的矩形创建自定义尺寸卡片。
- 创建后工具回到选择状态，新卡片直接进入可编辑状态。

### 三种常见状态

1. **默认/悬浮**：指针经过时顶栏操作逐渐出现，顶栏表面提示此处可以拖动。
2. **已选中**：点击顶栏进入，使用主题强调色边框；正文不会因此开始选字，仍可从顶栏拖动。
3. **正在编辑**：点击正文一次直接进入，以中性深色编辑边框区分；文字光标和编辑菜单可用。

按下指针但还没有越过拖动阈值时，不会提前闪成拖动态。放开后才根据实际手势判定为单击或拖动。

### 拖动与调整大小

- 从顶栏拖动卡片。顶栏中的按钮不会触发拖动。
- 四条边和四个角都可直接调整尺寸，不需要先选中卡片。
- 拖动或缩放时会参与对齐和吸附；调整尺寸不会显示遮住内容的叠加层。
- 卡片未选中时正文滚动条隐藏；已选中且内容溢出时显示简约滚动条；正在编辑时也可滚动。

### 卡片顶栏

展开卡片顶栏包含折叠/展开、全屏、右侧栏、更多和连线等操作。按钮在悬浮时出现，切换状态使用短过渡，不应挤动正文排版。

- **折叠/展开**是同一个双向按钮。
- **右侧栏**按钮可以打开或折叠面板。用户主动折叠后，选择另一张卡片不会擅自重新打开。
- **全屏**与右侧栏之间使用位置连续的过渡。
- **更多**打开对象菜单。

### 两种复制

- `Ctrl C`、`Ctrl V`：复制所选空间实例。卡片仍引用原 Markdown，可把它理解为分身。
- `Ctrl D`：创建独立副本。OpenCanvas 新建一个 Markdown 文件，之后编辑互不影响。

右键菜单还提供默认尺寸、适应内容、折叠/展开、锁定等批量能力。锁定对象不会参与普通移动和整理；解锁后恢复。

## 5. Markdown 编辑器

### 所见即所得与文件内容

编辑区使用富文本视图，但保存结果是 Markdown。非编辑状态会渲染格式，而不是把 `++==...==++` 一类标记原样当成正文；编辑和只读使用相同排版令牌，避免切换时字距、换行和标题颜色跳变。

### 行内格式

选择文字后，浮动工具栏出现在选择附近，而不是固定挂在页面顶部。可使用：

- 粗体、斜体、下划线、删除线
- 高亮和文字颜色
- 链接与卡片链接
- 行内代码和数学

图片本身也可以被选中，随后进行替换、对齐、调整或删除；非选中卡片仍正常显示图片。

### 区块格式

输入 `/` 或使用区块菜单可创建/转换：

- 正文、一级/二级/三级标题
- 待办列表、无序列表、有序列表
- 引用、代码块、数学块
- 表格
- 可折叠列表和可折叠标题

### 标题和段落节奏

标题与上一段的距离大于普通段间距，与下一段也保留清晰呼吸空间。标题不是仅靠字号放大，而是作为新的内容区块开始；编辑态和预览态使用相同间距。

### 链接、提及和附件

- 输入 `[[` 搜索并链接另一张卡片。
- 输入 `@` 插入提及。
- 链接会进入反向引用索引，重命名或移动文件时应用同步更新可管理的引用。
- 图片、音频、视频和其他附件保存到 `attachments/`；Markdown 使用相对路径，应用内通过安全的本地资源协议显示。
- 非媒体附件显示为可打开的附件链接。

### 编辑结束

点击画布空白处或按 `Esc` 会退出卡片编辑并清除浏览器文字选区。输入法正在组字时，应用不会误把 `Esc` 当作画布命令。

## 6. 画布导航、框选、多选与吸附

### 缩放和平移

- 滚轮默认以指针所在位置为中心缩放，包括指针位于已选卡片上时。
- 只有当卡片已选中、正文确实溢出且指针位于可滚动正文时，滚轮才优先滚动卡片。
- 按住 `Space` 拖动或使用平移工具移动画布。
- 小地图显示视口与内容关系，可用于快速定位。

### 框选和复选

- 从画布空白处拖出框选矩形；框内对象会在释放前显示命中提示。
- Section 只有被框选矩形完整包含才算被选中，普通相交不会抢走卡片选择。
- `Ctrl` 点击卡片顶栏或对象，可添加/移除多选。点击正文仍优先进入编辑。
- 多选外框使用弱化的统一圆角，仅概括范围，不替代每个对象自己的状态。

### 对齐、间距和整理

多选工具栏提供：

- 左/中/右对齐，上/中/下对齐
- 水平或垂直等距
- 整理为横向、纵向或网格布局

整理只处理可移动的选择，并合并成一次撤销记录。卡片贴近时保留视觉缝隙，不做无依据的自动推挤。

### 吸附

- 普通对齐使用克制的命中范围；紧贴间距使用更严格范围。
- 吸附发生时临时显示参考线，不显示干扰阅读的距离数字或垂直距离短线。
- `Shift` 在本次拖动中增强吸附。
- `Alt` 在本次拖动中关闭吸附，便于自由微调。
- 移动和八向缩放使用同一套对齐语义。

## 7. Section 区块

Section 用于在同一白板上表达区域和成员关系，它不是文件夹。

### 创建

- 按 `G` 后在画布拖出区域，或单击创建默认尺寸 Section。
- 多选对象后按 `Ctrl G`，新 Section 会根据所选内容的联合边界创建，并在四周保留一致边距。
- 创建完成后直接选中新 Section，并允许就地命名。

### 成员关系

- 卡片、文字、嵌套白板和内层 Section 只有完整包含时才成为成员。
- 一个对象可以同时属于多个相交 Section。
- Section 可以嵌套；只有内层 Section 被外层完整包含时才建立嵌套关系。

### 选择和拖动

- 未选中的 Section 框体尽量不阻挡内部对象。点击 Section 空白区域选中 Section；直接拖未选中的框体不会意外搬走整组内容。
- Section 已选中后，拖动框体会让它和成员实时一起移动；成员不需要额外高亮，拖动过程中不应先静止、释放后再瞬移。
- 框选时只有整个 Section 被包含才选中它，局部接触只继续选择内部节点。

### 自动边距

当成员被移动或缩放到边缘附近时，Section 会吸附到规定边距；如果成员强行靠近或越过基准边界，框体会弹性扩展以恢复边距。压力消失后，Section 回到用户最后一次手动确定的基准框，而不是无限漂移。

Section 颜色同时作用于淡色表面、边框和标题胶囊，且与普通卡片及画布背景保持区分。

## 8. 连线

### 创建连线

1. 按 `C`，或点击卡片顶栏右侧的连线按钮。
2. 卡片四侧连接点和中心“自动”点临时显示。
3. 从所需连接点开始；预览线使用最终线条样式并跟随指针，不额外改成虚线。
4. 接近目标卡片时，即使指针还在卡片边界外，只要命中吸附范围，目标连接点和状态也会正确显示。
5. 点击或释放到目标连接点完成。按 `Esc` 取消。

中心点表示自动选择接入侧；手动选择四侧点后，该端点固定在指定侧，不会随相对位置变化自动跳边。

### 选择和编辑

选中线条后，端点和关键点显示在最上层，不被卡片遮挡。只有正在拖动节点时，其他线条才临时淡化；放开后立即恢复，不因卡片保持选中而长期变淡。

- 拖动前后端点可重新连接到其他节点或连接点。
- 默认曲线具有来自两端方向的自然弯曲，但不预先堆满可见控制柄。
- 点击每一段中点可添加一个真正的关键点；新分段继续提供自己的中点。
- 双击关键点删除它。
- 直线和折线使用与其几何相匹配的控制方式。

### 标签

标签放在线上，通过与画布同色的透明/遮罩区域让线条在文字下方自然断开。第一段中点位置由标签本身接管，不再叠加一个点；拖动标签相当于拖动该关键点，双击标签直接在原位置编辑文字，不打开另一个输入小窗。

### 样式菜单

菜单悬浮在整条连线的上方合适位置，并限制在窗口内。可设置：

- 标签文字和颜色
- 起点/终点箭头、无箭头、单向或双向
- 曲线、折线、直线
- 三档线宽（均保持清晰可见）
- 实线或虚线
- 删除连线

线条本身和编辑状态不使用多余阴影。

## 9. 嵌套白板

按 `W` 后在画布单击或拖出矩形，创建一块子白板并把它放入当前白板。嵌套白板使用独立于画布背景和普通卡片的表面颜色，并以简略预览展示内部节点。

- 双击进入子白板。
- 左上角路径显示进入路线。
- 同一白板可以被多个父白板引用，也可以在多个位置出现。
- OpenCanvas 会阻止直接或间接把白板放入自身形成循环。
- 移除当前嵌套实例不必删除子白板实体；删除实体前会检查其他引用。

## 10. 文件目录与项目

### 文件目录是真实组织

“文件”视图对应 `notes/` 内的真实目录。层级通过缩进和图标左侧的小箭头表达。

- 点击箭头折叠或展开文件夹。
- 右键根目录或文件夹可新建卡片/文件夹。
- 卡片和文件夹支持重命名、拖动移动、移动对话框、回收站和打开本地位置。
- 拖动到文件夹时显示移动、无变化或无效反馈；悬停折叠文件夹可自动展开。
- 重命名或移动卡片不会改变它在白板中的坐标，白板引用会随实体更新。

### 白板层级与文件层级互不绑死

白板适合表达思考路径和上下文，文件目录适合归档、导出和与其他 Markdown 工具协作。二者平行存在：一张卡片可以属于某个目录，同时被任意白板引用，不需要复制文件，也不需要在视觉上标注“跨项目”。

### 整理为项目

在白板右键菜单选择“整理为项目”：

1. 为该白板创建并绑定一个项目目录。
2. 把当前白板引用的相关卡片整理到该目录，写入项目标记。
3. 此后在该白板新建的卡片默认进入项目根目录。
4. 用户可在项目内继续建立子目录；这些调整不会改变白板排版。
5. 解除绑定不会自动移回或删除文件。

项目是可选的真实文件组织需求，不是每块白板都必须拥有的属性。

## 11. 搜索、标签、链接与引用

- `Ctrl K` 打开快速打开器，可搜索并进入卡片或白板。
- 左侧栏搜索会按当前“白板/卡片/文件”模式筛选。
- 标签可用于跨目录聚合主题；不要为了白板布局重复建立相同文件夹。
- `[[卡片名]]` 建立卡片链接；引用关系可在侧栏或卡片上下文中查看。
- 文件移动和受控重命名会更新应用管理的相对链接；外部编辑器批量改名后，应重新进入应用并查看完整性中心。

## 12. 右侧栏与全屏阅读

选中卡片后，可从顶栏打开右侧栏。右侧栏实时显示当前目标；在画布空白处取消选择后，面板保留上一张内容。只有选中新卡片时内容才切换。

如果用户主动按按钮折叠右侧栏，该偏好保持；之后选择新卡片不会自动展开，直到再次主动打开。

全屏用于沉浸阅读或编辑。全屏、右侧栏和画布之间使用连续过渡，减少内容“瞬移”感。全屏时左侧栏仍可从边缘拖动调整宽度。

## 13. 导入、导出与格式损失

所有导入都应先看预览。取消预览不会修改知识库；确认后以事务提交，失败会回滚本次新增或变更。

### OpenCanvas ZIP

这是完整备份和迁移格式，包含：

- Markdown 卡片和目录
- 白板、空间实例、Section 关系和手动基准
- 连线、端点、关键点、样式和标签
- 嵌套白板、桌面布局和附件

需要在另一台设备或另一份知识库中完整恢复时，优先使用此格式。

### Obsidian Canvas

OpenCanvas 可导入和导出 `.canvas`：

- 卡片映射为文件节点，文字映射为文本节点，Section 映射为 group。
- 嵌套白板映射为 OpenCanvas 专用链接。
- 标准 Canvas 能保留连线端点、方向、标签和颜色，但不能完整表达 OpenCanvas 的关键点、曲线类型、虚线和精确线宽。
- Obsidian Canvas 没有显式多 Section 字段；导入时按 group 几何重新计算包含关系。

### Heptabase / Markdown ZIP

可迁移：Markdown 笔记、目录层级、相对附件。  
不可迁移：白板坐标、Section、连线、嵌套白板关系，因为 Heptabase 的 Markdown 导出本身不包含这些空间数据。

OpenCanvas 不把随版本变化的第三方专有数据库当成稳定开放写入格式。保留原始导出 ZIP，不要在首次导入成功后立刻删除来源。

### 安全限制和冲突

- 单个导入文件上限为 200 MB；解压过程还有文件数量、单文件、总大小和压缩比保护。
- ID、路径或附件同名冲突会在预览中报告，并通过新 ID 或安全重命名处理。
- 导入路径必须留在知识库内，不能使用 Windows 设备保留名或大小写冲突名称。

## 14. 保存、历史、回收站与恢复

### 保存状态

左下角状态会显示：

- **已保存**：计划内写入已经落盘。
- **正在保存**：有写入进行中。
- **保存失败**：打开知识库菜单查看错误并“重试保存”。
- **外部修改**：磁盘文件和应用内未保存编辑发生冲突，自动保存暂停。

关闭应用前，重要编辑应等待“已保存”。

### 外部修改冲突

当同一文件在外部编辑器中修改，而应用内也有未落盘内容时：

- **用磁盘**：放弃当前应用内冲突版本，重新读取磁盘。
- **用应用内**：以应用内版本覆盖磁盘；覆盖前保留文件历史。

不确定时，先在资源管理器复制冲突文件和知识库，再选择。

### 文件历史

每次有意义的覆盖写入前，OpenCanvas 在 `.opencanvas/history/` 保存历史。设置中可调整每个文件保留 10、30、60、100 或 200 个版本。纯粹平移或缩放视口不会反复制造无价值历史。

从卡片、白板或恢复中心打开“版本历史”，查看时间和大小并恢复。恢复会重新载入磁盘状态。

### 回收站

删除卡片、文件夹或白板时，资料进入 `.opencanvas/trash/`，可从知识库菜单的“回收站”恢复。永久删除不可撤销，只在确认目标和备份后执行。

### 恢复与完整性

“恢复与完整性…”会检查：

- 缺失实体引用
- 断裂连线
- 缺失附件
- 上次中断的导入或文件计划事务
- 可用历史版本与自动恢复记录

应用启动时会清理无效临时文件，并尝试回滚未完成事务。界面显示“部分文件正在等待修复”时，应打开恢复中心查看具体来源；不要仅靠重启掩盖问题。

## 15. 设置、外观和面板

设置包括：

- 当前知识库位置、在资源管理器中打开、切换位置
- 亮色/深色主题
- 文件历史保留数量
- 重新打开首次引导、完整用户手册和“关于与诊断”

“关于与诊断”会显示应用版本、运行环境、知识库位置、保存状态和对象数量。点击“复制诊断信息”生成可粘贴到问题报告中的纯文本摘要；摘要不会读取笔记正文、附件内容或文件清单。反馈前仍请检查知识库路径是否需要遮盖。

主题使用沉稳绿色作为强调色，亮色与深色分别拥有匹配的背景、卡片、嵌套白板、Section、文本和系统标题栏颜色。卡片阴影保持克制，状态主要由边框表达。

左右侧栏均可拖动边缘调整宽度。拖动时分隔线高亮；释放后保留用户布局。全屏卡片不会禁用左侧栏调整。

## 17. 故障排查

### 为什么浏览器测试版看不到 Markdown 文件？

`http://127.0.0.1:5173/` 是开发测试页面，使用浏览器本地存储，不代表桌面文件层。验证真实 Markdown、附件、资源管理器、安装、退出恢复和文件锁时，必须使用 Electron 桌面版。

### 卡片无法滚动

先确认卡片正文确实溢出，并已选中或正在编辑。未选中卡片隐藏滚动条，滚轮用于缩放画布。

### 点击正文却不能编辑

按 `Esc` 取消连线、平移、创建等工具，确认当前为选择工具，再单击正文。卡片顶栏只负责选择和拖动，不会进入编辑。

### 图片在未选中卡片中不显示

确认附件仍在 `attachments/`，Markdown 使用相对路径，并在“附件管理”和“恢复与完整性”中检查缺失引用。若只在安装版失败，记录应用版本和附件文件名后再复现，不要把附件复制进程序目录。

### 文字发糊或排版切换跳动

把画布缩放恢复到 100% 检查；任意非整数缩放都会产生浏览器栅格化差异。若 100% 下仍不同，比较编辑/选中/未选中状态并记录同一卡片截图。

### 拖动 Section 时成员不同步

确认先点击 Section 空白区域把 Section 本身选中，再拖动框体。未选中的 Section 会尽量让内部对象保持可操作。若已选中仍在释放后才瞬移，应视为交互缺陷并记录白板、嵌套关系和复现步骤。

### 保存失败或一直等待修复

1. 点击知识库状态查看具体错误。
2. 打开“恢复与完整性…”。
3. 确认磁盘空间、目录权限、同步盘和外部编辑器文件锁。
4. 先复制整个知识库，再使用修复或历史恢复。
5. 问题未解决前，不要永久清空回收站或历史。

### 外部修改弹窗反复出现

检查是否有 Obsidian、同步工具、编辑器或杀毒程序持续写入同一目录。一次只保留一个主动编辑者；同步盘环境尚需额外实机验证。

### 找到实际文件

在文件、卡片或白板上右键，选择“打开本地位置”；也可从设置打开整个知识库。

## 18. 升级、卸载与备份

### 升级前

1. 等待状态显示“已保存”。
2. 导出一份 OpenCanvas ZIP。
3. 复制整个知识库目录到另一个位置。
4. 阅读目标版本发布说明和已知限制。

当前读取器能读取旧版白板并在内存中迁移，只有真实修改后才写回当前格式。尽管如此，不应把兼容读取当作备份替代品。

### 卸载

知识库位于独立目录，正常卸载应用不应删除它。卸载前仍建议打开本地位置并确认资料存在。不要在卸载器或手动清理时删除自己选择的知识库目录。

### 建议备份策略

- 每次重要整理或导入前：导出 OpenCanvas ZIP。
- 每周：复制整个知识库目录到另一块磁盘或版本化备份位置。
- 每月：随机恢复一份 ZIP 到临时知识库，确认卡片、附件和白板可以打开。
- 同步不等于备份；误删和损坏可能被同步到所有设备。

## 19. 当前边界

1.0.10 聚焦单机个人核心闭环，尚未提供：

- 云同步和多人实时协作
- 移动端
- PDF 标注
- 插件 API
- 日记、聊天和思维导图模块
- 稳定版自动更新和 Windows 代码签名

真实触控/手写笔、OneDrive 和第三方文件锁、用户真实 Heptabase 导出、大规模历史知识库仍需要实机终验。浏览器自动化通过不等于这些环境已经验证。

## 20. 术语表

- **知识库（Vault）**：包含 `notes/`、`boards/`、`attachments/` 和 `.opencanvas/` 的根目录。
- **卡片（Card）**：以 Markdown 保存的笔记实体。
- **实例（Placement）**：实体在某个白板上的一次空间出现。
- **分身**：同一卡片实体的另一个实例，正文同步。
- **独立副本**：拥有新 ID 和新 Markdown 文件的卡片。
- **白板（Board）**：保存空间实例、Section、连线和视口的 JSON 文档。
- **桌面（Desktop）**：只放置根级白板的顶层无限画布。
- **嵌套白板**：某块白板在另一块白板中的引用实例。
- **Section / 区块**：白板内的视觉区域和多重成员关系，不是文件夹。
- **项目**：可选的真实文件目录，与某块白板绑定后决定新卡片默认保存位置。
- **附件**：保存在 `attachments/` 的图片、音视频或其他文件。
- **完整备份**：OpenCanvas ZIP；普通 Markdown ZIP 不包含完整空间关系。

如果只想立即开始，请读 [十分钟上手](quick-start.md)；如果要理解数据结构，请读 [开放格式](open-formats.md)。
